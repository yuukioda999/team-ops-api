# 004 役割と権限

## 概要

チームのメンバーは、代表・役員・コーチ・保護者のいずれか(複数可)の役割を持つ。できる操作は役割で決まる。

## ユーザーストーリー

- 代表として、役員に招待や名簿の管理を任せたい
- コーチとして、練習の連絡は自分で送りたいが、名簿の管理はしたくない
- コーチ兼保護者として、1つのアカウントで両方の立場を持ちたい

## 役割

- 1人が複数の役割を持てる(例:コーチ兼保護者)。できる操作は、持っている役割の和になる
- 代表は各チームに必ず1人だけ

## 権限表

| 操作 | 代表 | 役員 | コーチ | 保護者 |
|---|:-:|:-:|:-:|:-:|
| チーム名・競技の変更 | ○ | | | |
| 招待リンクの発行・無効化(002) | ○ | ○ | | |
| 参加申請の承認・却下(002) | ○ | ○ | | |
| 役割の変更(役員の任命・解任を含む) | ○ | | | |
| 代表の交代 | ○ | | | |
| メンバーの除名 | ○ | ○ ※1 | | |
| 選手の登録・編集・削除・CSV取込(003) | ○ | ○ | | |
| 名簿の閲覧(全員分)(003) | ○ | ○ | ○ | |
| 名簿の閲覧(自分に紐づく選手のみ)(003) | | | | ○ |
| お知らせの作成・送信(005) | ○ | ○ | ○ | |
| お知らせの閲覧(自分が宛先のもの)(005) | ○ | ○ | ○ | ○ |
| 既読・配信状況の確認、再通知(006) | ○ | ○ | ○ ※2 | |
| 監査ログの閲覧 | ○ | | | |

※1 役員は、代表と他の役員を除名できない
※2 コーチは、自分が作成したお知らせのみ

## 受け入れ基準

| ID | 前提 | 操作 | 結果 |
|---|---|---|---|
| AC-004-01 | 権限表のすべての操作 × すべての役割 | APIを呼ぶ | ○の組み合わせだけ成功し、それ以外は403を返す(権限表を元にした網羅テストで確認する) |
| AC-004-02 | コーチ兼保護者 | お知らせを作成する | 作成できる(役割の和) |
| AC-004-03 | 代表 | メンバーの役割を変更する | 変更され、本人にメールで通知する。監査ログに変更前と変更後を残す |
| AC-004-04 | 代表 | 役員のメンバーを指定して代表を交代する | 指定したメンバーが代表になり、元の代表は役員になる。両者にメールで通知する |
| AC-004-05 | 代表 | 役員でないメンバーに代表を交代しようとする | できない。先に役員に任命するよう表示する |
| AC-004-06 | 代表 | 自分を除名する、または自分の代表の役割を外す | できない。先に代表を交代するよう表示する |
| AC-004-07 | 役員 | 代表または他の役員を除名しようとする | 403を返す |
| AC-004-08 | 代表または役員 | メンバーを除名する | 除名されたメンバーは直後からチームのデータを見られない(404)。選手との紐づけも外れる。監査ログに残す |
| AC-004-09 | 役割をすべて外されたメンバー | — | 役割が1つもない状態は作れない。最後の役割を外す操作は除名として扱い、確認を表示する |
| AC-004-10 | 役割が変更された | 変更前の役割でしかできない操作を行う | 次のリクエストから新しい役割で判定される(キャッシュで古い権限が残らない) |

## 対象外

- 役割の追加・名称変更(第2弾以降)
- 操作ごとの細かい権限設定(チームごとのカスタマイズ)

## 補足

- 権限の判定は Laravel の Policy に集約し、Controller に条件分岐を書かない
- 権限表はテストのデータとしても使い、表とテストが食い違わないようにする
